# 安全说明

Fnet 处理的是**不可信的流量包**，并且会调用外部工具。本文说明它的安全边界、
已知限制与部署建议。

## 威胁模型

Fnet 假设：

- 运行它的机器是可信的，使用者是合法的分析人员；
- 输入的 pcap/pcapng 可能包含恶意载荷、畸形协议、超大字段或压缩炸弹；
- 外部工具（tshark、foremost、binwalk、aircrack-ng 等）本身可信，但可能
  被畸形输入触发崩溃。

Fnet 不假设：

- 浏览器所在网络可信；
- 流量包里的内容可以安全执行；
- 多用户共享同一实例是安全的。

## 本地优先

- 默认绑定 `127.0.0.1`，不监听外部网卡。
- 启动时生成随机 token，注入首页；所有写操作与敏感读操作要求
  `X-Fnet-Token`。
- 服务不主动联网。“检查更新”只提示从项目仓库获取版本。
- 若确需远程访问，请使用 SSH 隧道或带认证的反向代理；不要直接
  `--host 0.0.0.0` 暴露到公网。

## 输入处理

- 上传只接受 `.pcap/.pcapng/.cap/.dmp/.etl`，文件名经白名单字符清洗，保存
  到 `~/.cache/fnet/uploads/`，不会按用户提供的路径覆盖任意文件。
- 默认上传上限 1 GiB，可在配置里调整 `max_upload_mb`。
- 静态文件服务对路径做 `resolve()` 与前缀校验，阻止 `../` 目录穿越。
- JSON 请求体上限 4 MiB；文本解码输入上限 2 MiB。
- 首页 CSP 限制脚本/样式/连接只能来自 `self`（仅放行注入 token 的内联脚本）；
  响应带 `nosniff` 与 `no-referrer`。

## 不执行流量包内容

Fnet 不会：

- 反序列化流量包中的 Java/PHP 对象；
- 运行 Webshell 载荷；
- 打开流量包里的可执行文件；
- 把 pcap 字段拼接进 shell 命令。

外部工具通过参数数组调用（`subprocess.run([...])`，无 `shell=True`）。协议
解析全部交给 `tshark`，解密算法（AES/RC4/MD4/RSA/GCM）是纯 Python 实现，
只做字节变换。

## 子进程与取消

- 所有子进程都有超时；用户取消时通过 `cancel` 事件终止进程组。
- `tshark` 字段名先经 `tshark -G fields` 校验，避免未知字段导致整条查询
  静默失败。
- 外部工具缺失时功能报错并继续，不会让整个任务崩溃。
- “在 Wireshark 中打开”只在用户点击时启动本机 Wireshark（参数数组，不经
  shell）；未安装或路径不可用时返回提示，不会回退到其它程序。
- `/api/packet` 只接受任务 ID 与数字帧号，不接收任意路径。

## 资源限制

- 日志按任务缓冲，前端用增量 cursor 拉取，避免重复传输。
- 文本/表格输出有行数上限（通常 300 行或 800 行），防止超大流量包耗尽内存。
- 上传、JSON、解码都有上限；任务输出写入独立目录，便于清理。

## 已知限制

- WebUI 无内置 TLS、无多用户/权限模型；token 只防跨站请求，不防本机其它
  进程读取页面。
- 浏览器 `localStorage` 保存主题、部分设置与“最近使用”的功能编号，不会保存
  token。
- 任务历史 `~/.cache/fnet/jobs/<id>/job.json` 会保存该次分析的参数（可能
  包含用户输入的密码、密钥或路径），以便“一键重跑”。共享机器上请使用
  `FNET_HOME` 隔离，或分析结束后删除对应历史任务。
- 结构化结果 `findings.json` / `findings.csv` 会把抓到的账号、哈希、flag、
  解密明文等集中保存在同一任务目录，敏感程度往往高于日志。导出或分享前
  请确认内容，必要时使用 `FNET_HOME` 隔离并在分析结束后删除任务目录。
- 某些功能（Wi-Fi 破解、RDP 重放、CS 解密）依赖外部工具或第三方库，其
  安全性由对应项目负责。
- pcap 解析的健壮性最终取决于 `tshark` 版本；建议保持 Wireshark 更新。

## 合法使用

Fnet 仅用于合法的教学、CTF 竞赛、取证与**获得授权**的安全测试。请勿用于
未经授权的网络监听、凭据窃取或入侵。使用者对自己的行为负责。

## 报告问题

发现安全问题请通过项目仓库的 Issue 私下联系维护者（不要在公开 Issue 中粘贴
真实流量包或凭据）。仓库地址：<https://github.com/fyfhcgch/Fnet>。
